Level 2 of 5

Defined · ORBIT: Repeatable

AI use becomes a shared, versioned asset

Named workflows exist and are documented. Project configuration lives in the repository next to the code it serves. A second engineer can reproduce the first one’s results. AI still suggests; people still execute.

Entry gate
First named workflow with its configuration committed to version control, reproduced end to end by a second person.The insight: AI use becomes an artifact, not a habit.

Requirements

People & Skills

  • Role-based enablement exists for engineers, reviewers, and leads
  • A practice guild or equivalent shares workflows and failures on a cadence
  • Onboarding includes the team’s named AI workflows

Process & Workflow

  • Named workflows are documented with owner, trigger, and expected output
  • Golden-path templates cover the most common workflow types
  • Prompts and context assets are versioned with the code they serve

Platform & Tooling

  • Project configuration (CLAUDE.md or equivalent) lives in every active repo
  • A shared registry covers approved extensions, MCP servers, and scaffolds
  • New projects start from a standard AI-ready scaffold

Governance & Risk

  • Review standards for AI-generated changes are written and applied
  • AI-generated content is labeled with provenance in commits or PRs
  • A defined process approves new tools and integrations

Measurement

  • Adoption is tracked per named workflow, not per seat
  • Qualitative before-and-after is captured for each workflow
  • Utilization data identifies which workflows spread and which stall
