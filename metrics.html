Appendix

The metrics catalog

Everything worth capturing in an AI-enabled SDLC, and how to get ROI signal out of each Claude surface. Turn the plumbing on at Level 1; let the numbers start governing at Level 4. Baselines come first: capture 4 to 12 weeks of pre-AI delivery data before rollout, because the before-state cannot be reconstructed later.

Per-surface: where the ROI signal lives

Claude Code, the instrumented surface

The easiest ROI story, because the telemetry is native and the output lands in systems of record. OpenTelemetry export (opt-in, org-configurable) emits sessions, active time, lines of code, commits, pull requests, token usage by type, and per-request cost with model, agent, and skill attributes, so spend decomposes by team, workflow, or ticket. The Claude Code Analytics API adds daily per-user productivity aggregates without running a collector, and the analytics dashboard reports lines accepted, suggestion accept rate, and GitHub-integrated contribution metrics. ROI recipe: tag sessions with project and ticket identifiers, then compute cost per merged PR and cycle-time delta against your pre-AI baseline.

Claude Cowork, the event-based surface

Trickier: the output is documents, analyses, and decisions rather than commits, so there is no merge event to anchor on. What you can capture: admin dashboard and Analytics API report sessions, active users, per-user activity, and skill and connector invocations alongside Chat and Code figures; OpenTelemetry events cover tool and connector calls, files read or modified, skills used, and whether each action was approved manually or automatically. ROI recipe: define named workflows (a report produced, a deck drafted, a research sprint), baseline the human time-to-deliverable before rollout, then measure time-to-deliverable and deliverables per person after. The manual-vs-auto approval ratio doubles as a trust curve: watch it shift as confidence grows. Correlate OTEL events with Compliance API records via the shared account identifier for the governance story.

Claude chat, the survey-plus-sampling surface

The hardest attribution, because work leaves no artifact trail the organization owns. Available signal: usage analytics by product, model, and skill; the Enterprise Analytics API for per-user engagement and cost; spend limits per group. ROI recipe: pick the two or three highest-volume use cases from the analytics, run short time studies or paired-task comparisons on those specific workflows, and extrapolate only within them. Complement with quarterly pulse surveys (GitHub’s research pairs telemetry with perception for exactly this reason) and sampled work-product review. Resist the temptation to claim organization-wide hours saved from message counts; it will not survive scrutiny, and it teaches clients to distrust the numbers that are real.

The ROI capture ladder

Tell clients the honest sequencing: instrumented (Claude Code: native telemetry, artifact trail, cleanest ROI) → event-based (Cowork: OTEL events and workflow baselines, good ROI with modest design effort) → sampled (chat: analytics plus time studies and surveys, honest but bounded claims). Start every engagement by turning on what is free to record, and spend the design effort where the client’s value actually concentrates.
